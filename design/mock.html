Resilient sync for unreliable networks

A retry policy should protect user work without turning a brief outage into a long queue of invisible requests.

Backoff behavior

Each failed request returns to the local queue with an increasing delay. The client should keep editing available and make the pending state visible in the note header.

Cap exponential backoff at five minutes. Reset the delay after the first successful sync and preserve queue order for edits to the same note. Stamp preview

What the reader sees

The saved indicator changes to Pending while requests wait. If a note remains unsynced after three attempts, show a quiet action that lets the reader retry now.

Conflicts should never replace local content. Create a recoverable copy and explain what changed before asking the reader to choose a version.
